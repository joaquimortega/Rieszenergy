I reviewed `scripts/export_self_contained.py`, the explanation in `comparator/README.md`, and NOTEBOOK N43. The exporter still traverses the root import DAG, removes local import lines, and inlines each source body in dependency order. The new code saves the standalone environment's `mainModule`, sets it to each source module immediately before that module's body, and restores the saved value after the last section. This addresses Lean-generated private proof names such as `harmonicBasisDegree._proof_4`; it does not insert a theorem, alter a stated type, or replace a proof with an axiom.

The prior hygiene mechanisms remain in place. Each inlined body is wrapped in `section ... end`, which confines file-level `open`, variables, and local options; the source tree's file-level `set_option` commands are resource settings. `auxLemmasExt` is reset once at every module boundary so its module-local naming cache does not carry into the next source body. Bare file-private declaration names and their bare references receive a module prefix; dotted declarations are excluded. A scan of the current 105-source traversal found 238 such private declarations and no collisions among the generated prefixes. No source module directly manipulates `mainModule` or the auxiliary-lemma cache.

These transformations address namespace and elaborator-state differences caused by merging files. They do not weaken the comparator's statement matching, axiom traversal, or kernel replay: those remain separate checks in `scripts/run_comparator.py` and the pinned comparator. The private-name substitution is lexical, so this review alone cannot establish equality of the selected statements and their transitive definitions. Standalone elaboration and the full strict comparator must establish those claims for the generated file.
